## 3. 고른 해결 방법

| 기능 | 해결 |
|---|---|
| 다른 사람의 변경 보기 | 어려운 해결(`st.fragment(run_every=4)`로 4초마다 갱신) |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결(지원 단계에서 자리 계산으로 막음, 마감 뒤에는 "규칙을 지키는 배정 없음"과 이유 안내) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결(승인 직전 재검사, 투표가 끝난 순서로 처리) |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결(`tf_members`의 `(team_id, slot_no)` 기본키와 `student_id` 유일성 제약, 쓰기는 advisory lock으로 직렬화) |
| AI 응답이 늦을 때 | 어려운 해결(모델마다 스레드로 전체 120초를 재서 끊고 다음 모델로 넘어감) |
| 3차 모델까지 실패 | 어려운 해결(5가지 검사를 모두 통과하는 배정을 완전 탐색으로 찾음, `rules.solve`) |
| AI 대기 중 화면 | 어려운 해결(몇 차 모델을 몇 초째 기다리는지 `assign_status`에 표시) |
| DB 일시정지 막기 | 쉬운 해결(마감 날 11/2에 배포한 앱을 써서 DB 요청을 만듦) |

## 6. 클로드가 잘못 추론한 사례

- 사례: 클로드가 만든 규칙 테스트(`test_rules.py`)에서, 필수 포함 역할 자리 계산을 잘못 이해해 "기획자(보조 웹 프로그래머) 1명에 프론트엔드 디자이너가 있는 3명 팀에 보고서 작성자가 지원하면 막혀야 한다"고 기대했다. 실제로는 3명이 되어도 남는 자리 1개로 부족한 필수 역할 1개를 채울 수 있어 막으면 안 되고, 4명이 될 때 막혀야 맞다.
- 알아챈 방법: 테스트를 실행하자 `AssertionError`가 났고, 공고의 자리 계산 규칙(남는 자리 수 < 채우지 못한 필수 역할 수)을 다시 대입해 기대값이 틀렸음을 확인했다. 클로드가 테스트를 고쳐 통과시켰다.
- 근거: 커밋 [해시 입력]
